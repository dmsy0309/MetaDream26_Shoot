# 개인정보와 배포 설정

## 저장소에 넣지 않는 정보

- 개인 이메일은 GitHub noreply 주소로 대체합니다. 과거 작성자 정보도 정리한 이력을 사용합니다.
- OS 사용자명이 든 절대 경로, 개인 SSH 계정, 실제 서버 IP·Tailscale 호스트명은 문서와 증거 자료에서 익명화합니다. 원본 해시와 분석 결과는 유지하고 경로만 바꿉니다.
- `Docs/screenshots/`, `.Recovery/`, 리플레이, `.pending`, `.env*`, `*.local.json`, 개인키, 관리자 토큰은 Git에서 제외합니다. 캡처는 공유 전에 화면 내용도 확인합니다.
- 빌드·테스트 로그에는 기기 경로가 다시 들어갈 수 있습니다. 원본 로그는 `Logs/`에 두고 공유할 기록은 먼저 익명화합니다.

## 게임의 개인정보 처리

- 컴퓨터명, OS 사용자명, OS 정보, 하드웨어/설치 기기 ID, 내부 IP를 리플레이 기기 정보로 수집하지 않습니다. 옛 리플레이 필드는 호환성을 위해 빈 값으로 유지합니다.
- 접속 시에는 컴퓨터명 대신 프로세스마다 새로 생성되는 임의 세션 별칭을 사용합니다. 같은 실행 중 재접속을 지원하며 PC·계정·하드웨어에서 파생하지 않습니다.
- 리플레이에 참가자의 기기 별칭이나 접속 주소를 기록하지 않습니다. 직접 입력한 닉네임·방 이름·채팅·게임 진행은 리플레이 내용이므로 개인정보를 입력하지 않도록 주의합니다.
- 로컬 리플레이 저장은 유지합니다. 자동 업로드는 기본으로 꺼져 있고 기존 `.pending` 파일은 자동으로 재전송하지 않습니다.

## 메인 서버 설정

기본값은 로컬 `127.0.0.1:47800`입니다. 실제 게임 서버 목록 주소는 `-master host:port`, `METADREAM_MASTER_HOST`, 또는 전용 서버의 로컬 JSON 설정으로 지정합니다. 예제 JSON을 복사해 `server.local.json`으로 두고 `-config server.local.json`으로 실행할 수 있습니다. 배포 스크립트에는 `MD_MASTER_SSH`로 실제 SSH 대상을 전달합니다.

## 리플레이 업로드를 명시적으로 사용할 때

업로드를 원하는 게임 호스트 실행 환경에 아래 세 값을 별도로 설정합니다. 실제 주소와 키는 저장소에 넣지 않습니다.

| 환경변수 | 의미 |
|---|---|
| `METADREAM_REPLAY_UPLOAD` | `1`로 설정해야 활성화 |
| `METADREAM_REPLAY_UPLOAD_URL` | HTTPS 리플레이 서비스 기본 URL. 사용자정보·쿼리·fragment를 넣지 않음 |
| `METADREAM_REPLAY_UPLOAD_KEY` | 별도로 생성한 전송 키. 수신 서버에도 같은 환경변수로 설정 |

전용 서버는 추가로 로컬 설정의 `uploadReplays`를 `true`로 지정해야 합니다. 수신 서버는 키가 없으면 업로드를 거절하며 HTTPS 프록시 뒤에서 운영합니다. HTTP 업로드와 자동 재시도는 지원하지 않습니다.

과거 리플레이를 명시적으로 업로드하는 경우에도 압축 본문과 HTTP 메타데이터 헤더에서 기존 기기·계정·내부 주소를 제거합니다. 게임 데이터와 직접 입력한 닉네임 등은 유지합니다. 수신 서버가 연결상 알게 되는 송신 IP와 기존 저장 데이터의 보존·삭제는 운영자가 별도로 관리해야 합니다.

## 적용 범위

이 설정은 정리된 소스로 새로 실행/빌드한 게임에 적용됩니다. 이미 설치된 과거 실행 파일, 기존 로컬 리플레이, 운영 서버의 저장 자료는 자동 변경·삭제하지 않습니다. 로컬 복구 번들에는 정리 전 자료가 있으므로 외부에 공유하지 않습니다. 이력 정리 후 기존 복제본을 재사용할 때는 예전 커밋을 다시 push하지 않도록 주의합니다.
